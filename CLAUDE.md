# LXP-UX Refinement — Project Memory

## Core thesis (saved approach)
The Learning Experience Platform should be organised around **journeys**, not products. A "life event" is not a SKU lookup — it is a sequence of moments, emotions, decisions and conversations that unfold over time. The advisor's job is to navigate that sequence with the client.

## Advisor progression model (refined)
The advisor's posture **evolves** with experience:
1. **Reactive** (junior) — responds to client cues, runs a playbook.
2. **Observer / partner** (mid) — anticipates, asks the next question before client does.
3. **Guide** (senior) — informs client thinking with outcome- and consequence-focused framing. AI co-pilot supports throughout.

The lens is therefore not a binary toggle; it is a *path* the advisor walks. The LXP must teach that path.

## Two valid training framings
We design for both, as switchable lenses inside a single journey:

### 1. Client-vantage (inside-out)
The advisor is trained by inhabiting the client's experience first.
- What is the client *feeling* at each stage?
- What are they Googling at 2am?
- Which words trigger trust vs. which trigger defensiveness?
- The advisor learns empathy → diagnosis → recommendation.
- UI metaphor: a *timeline of the client's life*, advisor scrubs through it.

### 2. Advisor-reactive (outside-in)
The advisor reacts to a signal — a client-volunteered cue, a CRM trigger, a referral.
- Signal → diagnose → conversation script → product fit → follow-up cadence.
- UI metaphor: a *playbook / decision tree* the advisor runs at the moment of need.

A McKinsey-grade answer is **not** "pick one." It is to make both views first-class and toggle-able on the same journey object, because real advisors switch between them mid-meeting.

## What we are NOT doing
- Not listing products as the primary content.
- Not copying the existing Sanlam LXP UI patterns (page layout, sidebar treatment, card style) — original design only.
- The Sanlam logo mark IS allowed (user is internal to Sanlam, provided the file).
- Not adding filler stats, icons, or "AI slop" tropes.

## Journey grain
The right unit is a **wholesome life chapter** (e.g. "Getting Married" — spans roughly engagement through 18 months married), possibly nested inside a **multi-year life arc** (engaged → married → first child → home → retirement). Triggers exist *inside* journeys; they are not the unit.

## Visual direction (default until told otherwise)
- Editorial, calm, document-grade typography.
- One serif display + one humanist sans + monospace for meta.
- Restrained palette: warm off-white, ink near-black, one signal accent.
- No gradient hero blocks. Information density earns trust.

## Output format
Single HTML file using `design_canvas.jsx` so the user can compare 3–4 reframed concepts side-by-side. Each artboard is a high-fidelity working mock of one journey-centred approach.
